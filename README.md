## Описание проекта
В рамках проекта были организованны несколько классов, которые можно разделить на реализацию: приёма 3 типов задач из условия, задания типов контракта, проверку типов контрактов
### class APISimulate 
Реализация симуляции api задачи с номером и уровнем важности. Необходимо указать путь/название json файла. Функция get_tasks - стандартная для всех классов функция реализует вывод списка задач из api.
### class ReadFromFile 
Реализация симуляции задачи из json файла. Функция get_tasks - стандартная для всех классов функция реализует вывод списка задач из json файла.
### class RandomTaskGenerate 
Реализация симуляции задач. Функция get_tasks - стандартная для всех классов функция реализует генерацию случайных задач по сиду и вывод списка задач.
### class SourceChecker
Реализация проверки контракта для задачи. Функция check_task проверяет что ключи в словаре валидны. Функция check_source реализует проверку контрактов
### class EnumDescriptor
Реализация data-дескриптора для валидации статуса и приоритета задач
### class FinishTimeDescriptor
Реализация data-дескриптора для времени завершения задачи
### class Task
Реализация основного функционала задача: созданы поля priority, status, _finish_time, _created_time и обновлены поля _id, _description. Внутри класса реализованы защита неизменяемых полей id, created_time. Также реализовано вычисление deadline status и демонстрация non-data-дескриптора __str__
### class TaskQueue
Реализация итерируемой очереди задач на генераторе.
### class TaskProcessingError
Реализация класса ошибок для работы с workers
### class AsyncTaskExecutor
Асинхронная обработка реализации задач
### class TaskHandler
Протокол асинхронного обработчика задач
### class ExecutorError
Протокол обработчика ошибок
### class TaskProcessingError
Вывод об ошибке в существующем обработчике задач
### class ExecutorNotStartedError
Вывод об ошибке в несуществующей обработчике задач
Проделанная работа помогла узнать о принципе duck typing и работе с ним, почему и как используются Protocol и TypedDict, а также как реализовывать runtime-проверку условий.
Во время выполнения второй лабораторной удалось узнать о дескрипторах и @property и как они правильно используются.
В рамках третей лабораторной удалось понять как писать свои итерируемые коллекции и как работает ленивая фильтрация.
Во время выполнения четвёртой лабораторной удалось разобраться с асинхронным программированием на примере обработчика задач.
Было инетересно разобраться как работает функция async.sleep(n). Также пришло понимание работы с ошибками в асинхронном обработчике задач.
